# 深度智能体

深度研究智能体将同一思路应用于证据规模会超出单次对话容量的问题。运行时，planner 会选择相互独立的分支，并且只向每个工作智能体提供原始问题、分配给它的任务及其所需工具。同级分支的历史记录不会传入。最后一个阶段会综合各工作智能体保留的证据。请先运行这一模式，再检查其实现方式。

## 工作流边界如何变化

在整个模块 2 中，外层工作流负责管理范围和数据流。检索与深度研究对这一边界的划分方式有所不同。

- 索引工作流。开发者定义工作流，生成阶段接收 B 部分提供的有界检索资料包。
- 深度研究工作流。planner 在运行时创建分支。工作智能体接收特定任务的上下文，并存储证据以供综合。

对于必须根据中间结果进行调整的阶段，这两种工作流都可以在其中放置 ReAct 循环。

## 共享上下文为何会失效

单个ReAct循环将所有指令和观察结果保存在同一段历史记录中，因此早期证据会与每项新的工具结果争夺注意力。最终，历史记录本身也会成为问题的一部分。

*一个协调器分配聚焦的任务。各个独立的工作智能体通过共享存储返回证据，最后一步再将证据整合起来。*

- 溢出：证据和工具输出超出上下文窗口的容量。
- 上下文退化：相关证据虽已包含在上下文中，但权重不足（Liu et al.）。
- 干扰：一个分支的推理会分散下一个分支的注意力。

## 研究如何在工作流中推进

1 · 规划

编排器将问题拆分成相互独立的任务，使预定范围在工作开始前即可检查。

2 · 调研

每个子智能体都会在一个全新的上下文中接收一项任务，其中不包含其它分支的历史记录。

3 · 保存

工作智能体将研究结果写入共享的虚拟文件系统，这样即使其上下文结束，证据仍会保留下来。

4 · 综合

编排器读取已保存的证据并生成统一答案，其中的论断仍可追溯至各自的分支。

全新上下文并不是沙盒。

上下文隔离用于分离各分支的推理，而沙盒用于限制对操作系统的访问。下方的浏览器制品无法使用 shell；后续的手工实现示例则使用内存文件系统，让共享状态清晰可见。

## 动手试一试 · 规划、调研与综合

提出一个研究问题，观察智能体如何创建多个分支，并行研究精选的外部资料和本课程内容，然后撰写一份带引用的统一答案。每个工作智能体都会将输出流式传送到各自可聚焦的面板中，因此可以检查正在执行的操作，无须等待所有并行分支全部完成。

```
// Load the same-origin vendor bundle used by this example.

helpers.log("导入 OK");

const baseURL = cfg.url.startsWith("http") ? cfg.url : (window.location.origin + cfg.url);

  configuration: { baseURL, dangerouslyAllowBrowser: true, fetch: helpers.browserChatFetch() },
  apiKey:    cfg.needsKey ? helpers.getKey() : "no-key-needed",

  temperature: 0,
```

**▸ JS async (state, helpers) => { … }**

```
// Ask the agent a concrete question to drive the loop.
const question = "现在的 UTC 时间是几点？请使用 get_current_time 读取时钟。";
// Try another (uncomment one) and rerun to watch the trajectory change:
// const question = "What is the capital of France?";               // answered directly, no tool call
// const question = "What time is it, and is that AM or PM in UTC?"; // inspect whether the model requests the clock
const result = await state.agent.invoke({
  messages: [{ role: "user", content: question }],
}, { signal: helpers.signal });
helpers.log.details('图响应', result);
if (result.messages.some(m => m.response_metadata?.finish_reason === 'length'))
  throw new Error('图中的一条响应已达到 token 上限。调整预算前，请检查执行轨迹。');
if (!result.messages.some(m => m.tool_call_id && m.name === 'get_current_time'))
  helpers.log('未返回时钟结果。回复中有关当前时间的任何说法都缺乏依据。');
// Map LangGraph message objects to the role-tagged shape viz.messageList wants.
const roleFor = type =>
  /Human/i.test(type) ? "user"
  : /Tool/i.test(type) ? "tool"
  : /AI/i.test(type)   ? "assistant"
  : "system";
const trajectory = result.messages.map(m => ({
  role: roleFor(m.constructor.name),
  content: typeof m.content === "string" ? m.content : JSON.stringify(m.content),
  tool_calls: (m.tool_calls || []).map(tc => ({ function: { name: tc.name, arguments: JSON.stringify(tc.args || {}) } })),
}));
helpers.viz.messageList(trajectory, "LangGraph 轨迹 · .invoke() 返回的消息列表");
return {
  message_count: result.messages.length,
  final_reply:   result.messages.at(-1).content,
  message_types: result.messages.map(m => m.constructor.name),
};
```

## 3 · 保存并整合工作智能体的草稿

此示例依据模型知识撰稿：工作智能体有文件工具，但没有检索工具或提供的来源。文件保留的是草稿，并非经过独立核实的证据。工作智能体按顺序执行并共享已保存的文件。deepagents包为 Node.js 应用程序封装了类似模式。

以保存的草稿构建工作流

请一并设置目标与预期的文件路径。工作智能体依据模型知识撰写草稿，没有外部来源；所有预期的草稿都必须由本次调度执行写入且含有内容，才能进行整合。

创建共享草稿工具

工作智能体通过内存中的文件交换草稿。保存文件不代表其中的事实已获验证。

**▸ JS async (state, helpers) => { … }**

```
// Pull the LangChain helpers this agent cell needs.
const { tool, z } = state.deps;
state.vfs = {};
state.createWriteFile = dispatch => tool(
  async ({ path, content }) => {
    if (dispatch && !dispatch.current()) throw new Error("这次工作智能体调度已不是当前调度；此次写入未保存。");
    state.vfs[path] = content;
    dispatch?.writtenPaths.add(path);
    return "已写入 " + path + "（" + content.length + " 个字符）"; },
  { name: "write_file",
    description: "将完成的交付成果保存到可在多次子智能体调用之间持续保留的文件中。",
    schema: z.object({ path: z.string(), content: z.string() }) },
);
state.writeFile = state.createWriteFile(null);
state.readFile = tool(
  async ({ path }) => state.vfs[path] || ("（文件 " + path + " 未找到）"),
  { name: "read_file", description: "读取之前保存的文件。",
    schema: z.object({ path: z.string() }) },
);
state.listFiles = tool(
  async () => Object.keys(state.vfs).length ? Object.keys(state.vfs).join(", ") : "（尚未保存任何文件）",
  { name: "list_files", description: "列出所有已保存文件的路径。", schema: z.object({}) },
);
return { tools: ["write_file", "read_file", "list_files"], vfs_state: Object.keys(state.vfs) };
```
