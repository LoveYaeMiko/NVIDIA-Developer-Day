# 持续运行的智能体

在模块 3b 中，您发送消息时智能体才会运行。心跳和cron 任务可以启动无人值守的工作，智能体也可以将工作委派给子智能体。技能为运行中的智能体提供可复用的指令。每次运行仍使用智能体循环和 OpenShell 沙箱；会话、指令和触发条件决定运行的内容。您将安装一个技能，并观察一次由 cron 触发的写入。

## 触发器如何选择上下文和指令

本页中的每种机制都由以下三个参数描述：

- 会话决定一次运行继承谁的上下文。
- 指令通过文件或计划消息提供执行要求。
- 触发器决定何时开始运行。

下表展示了课程所用的配置。可以使用同样的三个字段对其它触发器类型进行分类；OpenClaw 还提供了其它会话模式。

| 名称 | 会话 | 指令所在位置 | 触发器 |
|---|---|---|---|
| 技能（下方运行） | 复用调用方的会话 | workspace/skills/<name>/SKILL.md | 本练习明确指定技能；自动选择须另行检查 |
| 心跳（仅介绍概念） | 此处为主会话 | HEARTBEAT.md | 网关计时器，默认约 30 分钟 |
| Cron （下方运行） | 此处使用隔离会话；每次触发都会新建 | 计划任务中的 payload.message | 本练习指定的单次计划时间 |
| 子智能体（仅介绍概念） | 新建会话，父智能体持有句柄 | 父智能体提供的任务指令 | 父智能体在轮次进行期间决定 |

OpenClaw 可以将 cron 任务绑定到
。本课程使用独立的 cron 运行，让每次演示都从空白会话开始。您将在本页运行技能和 cron 任务。Heartbeat 与子智能体任务分派仅作为表格条目介绍，本页没有单元会触发它们，因此无需等待它们运行。

## 步骤 1 · 读取技能及其操作手册

安装练习目录，其中包含带有 name/description 前置元数据的 SKILL.md，以及随附的操作手册。重新读取会验证这两个文件。接着，新对话会明确读取技能，并从操作手册获取参考码。判断是否遵循指令前，请检查工具事件及建议操作。这项练习测试的是明确指定的技能使用；自动选择需要另行进行发现测试。

与 Kickstart 使用同一个运行时。 您正在操作的就是在 Kickstart 页面上连接的那个 OpenClaw 智能体。
共享 OpenClaw 运行框架的健康检查、条件修复和日志。健康检查会运行命令并读取 toolSearch。仅当 toolSearch 已启用时，恢复操作才会更改它；清除会话和重启是独立的可选操作。运行时日志会在执行停滞时持续读取日志。

## 第 2 步 · 检查正在运行的智能体

调度作业位于网关上，而不是某个 HTTP REST 路由之后。因此， Control UI 使用的同一个 WebSocket 连接，也是您通过 cron 方法cron.list 、cron.add 和cron.remove 列出和管理这些作业的通道。cron 作业按照自身计时器触发，使持续运行的智能体无需人工介入即可执行操作。课程运行时会为本次演示创建隔离会话。如果连续性比隔离性更重要，OpenClaw 也可以将调度工作绑定到其它受支持的会话模式。

此单元会安装一项具有唯一名称的任务，并等待最多三分钟，确认计划执行成功。这项单次任务会要求在执行后自动删除，因此关闭页面后的工作也能受到限制。单元会验证新的文件参考码，并移除自己创建的任务，包括失败或按下“停止”时。请保持页面打开，直到清理完成。若清理失败，请保留记录中的任务 ID，并使用移除单元。证据文件会保留供您检查。

成功的执行记录与内容匹配的新文件，可证明写入是由计划任务触发，触发时并未发送新的聊天消息。
