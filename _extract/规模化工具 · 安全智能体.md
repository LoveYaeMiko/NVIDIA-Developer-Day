# 工具的规模化应用

在模块 1b 中，您将一个工具接入了智能体循环：模型请求调用一个具名函数，执行框架运行该函数，再将结果传回下一次模型调用。此处的往返过程并未改变，变化的是工具界面：模型必须从更多描述中作出选择，而每个工具背后都可能隐藏着更强大的能力。

本页沿用这一约定，从本地函数逐步扩展到搜索后端和子智能体。将子智能体用作工具 ，就是将一个专注于特定任务的智能体封装在单一模式之后，使外层工作流可以分派任务，而不暴露其全部内部能力。Model Context Protocol (MCP) 为客户端提供了一套标准方法，用于发现并调用由其它进程提供的工具。请在能力边界处使用它，并先验证服务器、身份和权限范围。这两种模式都能精简主循环的工具列表，并为模块 2 中限定范围的工作流奠定基础。

## 工具调用约定保持不变

下图呈现了模块 1b 中的循环。后续各节会改变模式的来源和执行器的行为，但模型仍会请求调用具名工具并读取其结果。

*模型请求使用工具，运行框架负责执行并返回结果，供模型做出下一次决策。*
输入模式描述提供给模型的参数名称、类型及必填字段。它不会执行工具，也不保证模型提出的参数安全。分派调用前，请检查返回的名称，解析参数并验证其值。下面的示例会显示所请求的调用，并在输入无效时停止。

## 模型如何在多个工具之间作出选择

有多个工具可用时，模型会结合名称、描述、参数模式、对话及任何tool_choice 约束来提出调用。各工具定义中的 description 说明该工具适用的场景。查看下方的工具规范节点可了解完整定义，或参阅函数调用指南 了解请求格式。

下方单元为模型提供两个工具和一个需要从中作出选择的问题，可视化结果会显示模型选择了哪个工具以及选择原因。
三条路径汇入同一个 LLM；修改任一工具的描述都会改变模型的路由方式。在任何使用工具的智能体中，描述字符串都是影响最为显著的提示词工程界面之一。

## 将 glossary_search 接入真实工具

该单元将glossary_search 接入页面内的 NVIDIA 术语目录。排序搜索无需密钥即可在浏览器中运行，并返回带来源链接的简短定义。课程共享的web_search 会对完整目录应用相同的排序方式。打开术语表浏览器 即可查看所有术语、阅读实时的webSearch 和instantAnswer 源代码，或自行运行查询。

下一节将执行器改为检索完整文章，同时保留相同 的工具约定。您可以观察后端发生变化时，约定如何保持不变。
名为
的工具很脆弱：一旦更换后端，您就必须更新所有引用该名称的提示词。名为
的工具描述的是调用方所需的能力。排序搜索、精确查询或更丰富的索引都可以置于该约定之后，无需更改智能体提示词。
每个节点都向共享状态对象写入数据，后续节点再读取这些数据。打开任一节点即可编辑其 JS 并单独重新运行，也可以运行整个图。

**在不改变工具的情况下替换执行器？**

## 更换后端，同时保持工具约定不变

此处以扁平的mountRunCell 脚本运行相同循环，只有一处变化：执行器。之前的搜索会为多个匹配项分别返回一段简短说明。此后端则会从该术语的缓存术语表页面中，获取最佳匹配项的完整文章。模式和循环均未改变；只是glossary_search 背后的数据源变得更加丰富。
它使用自然语言查询请求
，并读取返回的内容，却不知道是哪个后端作出的响应。可以先使用简短说明索引，之后再替换为完整文章或实时搜索，无需修改循环。如果不同后端采用不同方式确定匹配项，准确性可能会发生变化，但约定仍然有效。
保留 glossary_search 契约，改用功能更丰富的后端，返回最匹配术语的缓存文章。编辑问题并重新运行；全文文章涵盖向量数据库、RAG、LLM、AI 智能体和深度智能体。

**将一个专用智能体封装为单一工具？**

## 将整个智能体隐藏在单个工具之后

工具不一定是小型函数。整个子智能体也可以封装在一次工具调用之后。对于调用模型，子智能体仍表现为一项约定。在该约定背后，它可以查询数据库、运行代码或搜索代码库，无需向主循环暴露这些内部工具。

下方单元格通过一个自然语言工具提供子智能体，供其读取小型客户数据表。数据行不会加入主智能体的初始上下文，但子智能体返回的答案可能包含这些数据。这实现了上下文分离，但并未实施数据访问控制。
为主智能体提供一个由了解模式的子智能体支持的 query_customer_db 工具。调用方发送问题，并收到子智能体的答案。

## 使用 MCP 从独立服务器获取工具

Model Context Protocol (MCP) 为工具服务提供了标准形式。智能体通过tools/list 获取服务器的工具目录，并通过tools/call 调用所选条目。这些工具运行在独立进程中，智能体启动时会连接该进程并进行查询。由于各处采用相同协议，智能体无需为每台服务器学习新的接口，即可连接更多服务器。当工具发现和传输需要共享协议时，请使用 MCP。如果执行框架已经知道能力的位置和调用方式，则使用本地函数、仓库技能或直接的 API 调用。
请将
响应视为不可信输入。连接服务器之前：

- 验证其身份，
- 向用户显示所请求的能力，
- 授予满足使用需求的最小权限范围，
- 并将每项凭据绑定到该服务器对应的受众。
对于远程连接和 OAuth 发现，请拒绝私有地址和链路本地地址，并验证每一次重定向。
要求客户端负责用户同意、token 处理以及服务器端请求伪造（SSRF）控制。

下方的代码单元用纯 JavaScript 模拟一个小型 MCP 服务器，采用 MCP 定义的JSON-RPC 格式，但不包含传输层。智能体获取工具列表，将模式交给模型，再把tool_calls 分派回服务器的tools/call 处理函数。循环仍会请求工具、执行工具，再追加结果；工具发现和分派则改由服务器接口处理。
通过 tools/list 发现两个页面内 MCP 工具，再通过 tools/call 分派模型请求。智能体循环保持不变。

if (state.s1.finish_reason !== "tool_calls" || !Array.isArray(calls)) throw new Error("工具请求未完成；未运行任何工具。");
const ids = new Set();
const batch = calls.map(tc => {
  const schema = state.tools.find(tool => tool.function.name === tc?.function?.name)?.function.parameters;
  if (typeof tc?.id !== "string" || !tc.id.trim() || ids.has(tc.id)
      || tc.type !== "function" || !schema) throw new Error("已发现工具的请求批次无效；未运行任何工具。");
  ids.add(tc.id);
  const args = JSON.parse(tc.function.arguments);
  if (!args || typeof args !== "object" || Array.isArray(args) || (schema.required || []).some(key => !(key in args))) throw new Error("缺少工具参数。");
  for (const [key, value] of Object.entries(args)) {
    const type = schema.properties?.[key]?.type;
    const invalid = type === "integer" ? !Number.isInteger(value)
      : type !== "string" || typeof value !== "string" || !value.trim();
    if (invalid)
      throw new Error("参数不符合所发现的 string/integer 模式：" + key);
  }
  return {tc, args};
});
for (const {tc, args} of batch) {
  helpers.signal?.throwIfAborted();
  const out  = await state.mcpServer.request("tools/call", { name: tc.function.name, arguments: args });
  const txt  = out.content?.[0]?.text || "（无文本）";
  helpers.log.details("服务器 → " + tc.function.name, out);
  state.messages.push({ role: "tool", tool_call_id: tc.id, content: txt });
}
const s2 = await helpers.chatStream({
  messages: state.messages, max_tokens: 8196,
});
helpers.log.details("最终模型响应", s2);
if (s2.finish_reason !== "stop" || s2.tool_calls?.length || !s2.content?.trim())
  throw new Error("模型未返回完整的最终答案。");
return s2.content;
