## 二、课程要回答的两个问题

### 问题一：智能体是怎么运转的？

课程主页把智能体一句话讲完："将模型连接到工具和记忆，再通过路由决策持续运行，直至完成任务。"

然后它把这个说法拆成一根固定骨架 —— **感知 → 推理 → 行动** 的循环（模块 1），再逐步往上加东西：

- 让模型在行动之间"想一想" → **ReAct 循环**（1b）
- 把代码包装成模型能请求的**工具**（1c）
- 用**工作流**在模型调用之间插入确定性步骤（2a）
- 用**检索**把外部知识塞进上下文（2b）
- 用**规划器 + 子智能体**把任务拆到超出单次对话的规模（2c）

### 问题二：它凭什么被允许做这些事？

模块 3 把智能体从"页面一关就结束"搬到常驻运行时上：它有了工作区文件、记忆、技能、定时任务 —— 于是它开始**真的能改东西**了。模块 4 回答：这些能力由谁、在哪一层、用什么机制削减。

### 课程的核心立场

全文反复出现的一句话可以作为整门课的结论：

> **边界可以被强制，含义不能被强制。**
>
> 沙箱能限制文件、网络目标和系统调用，但无法判断"被允许的那条通道里传的字节是否有害"。

讲师在录音里用更直白的话说了同一件事："最好的防护是在外面防护，这叫进程外防护，不是进程内防护。"

## 三、学习目标与目标读者

课程主页列了 5 条学习目标（学员完成后应能）：

1. 构建基本的智能体循环，并识别其核心组件。
2. 在智能体系统中实现可靠的工具使用和函数调用。
3. 使用结构化路由模式设计和协调多智能体系统。
4. 使用 OpenShell 配置智能体身份，并确保智能体在沙箱中安全运行。
5. 部署和管理自主智能体，同时构建持久化技能库。

**但讲师对课程定位的说法和这个列表有微妙差异**，值得记下来：他在现场反复强调这是一门 **3 小时的体验课**——

> "我们这门课并没有告诉大家手把手的把这个实现写这个智能体的代码……我们重点是通过各种各样的操作来体会智能体的功能，然后他的弱点在哪里，我怎么增加了防护。"

也就是说：**目的是建立判断力，不是学会写框架**。想学写智能体代码，"那是在另外一门课里讲的"。他还提醒："我唯一担心的就是你在做的过程中不知道在做什么"—— 所以先讲原理图，再带跑实验。

### 模块 1 · 智能体基础：把循环立起来

**01a 智能体**是整门课的地基，做的事很"反常"：先不讲 LLM，而是先写一个**不用语言模型**的智能体 —— 一维轨道上一辆来回弹的小车，推理步骤只有两条 `if`。

| 环节 | 这一页怎么写 | 关键代码/字段 |
|---|---|---|
| 感知 | 只读当前位置与是否碰壁 | `perception = { position, atLeftWall, atRightWall }` |
| 推理 | 最初是两条 `if`，后来换成 DFS / BFS / A* / 模型 | `state.agent.direction` |
| 行动 | 改位置 | `state.env.position += action.move` |

这个设计是为了证明一件事：**循环框架建一次就够，之后只需要换中间那一步**。于是同一套迷宫循环里先后装了"永远向东"、DFS、BFS、A*，最后装进 `chat()` —— 模型通过 `choose_direction()` 返回方向，控制器在移动前**校验工具名与参数**。

这一页还讲了三个后面一直要用的判断：

- **各次调用不共享状态**。对话的"记忆"就是代码维护、每轮重发的 `messages[]`。（Chat Completions API 由代码存对话，Responses API 由服务器存线程 —— 但模型本身永远无状态。）
- **`reasoning_content` 不一定会出现**，要看实际返回的字段。
- **`finish_reason` 是循环的退出条件**：`"stop"` 最终答案、`"tool_calls"` 要求执行函数、`"length"` token 用尽。

**01b ReAct 循环**把上面这套变成可用的循环：给模型一份工具清单，它要么回答、要么请求执行工具，执行结果作为 `tool` 消息追加回去，再问一次 —— 直到 `finish_reason === 'stop'`。消息数组按"系统提示 → 用户问题 → 带 `tool_calls` 的 assistant → `tool` 结果"四轮增长。

这一页真正的重点是**上下文退化**（引 Liu et al. 2023："埋在长上下文中间的信息可能用不上"）。给出的缓解手段也是后面模块的伏笔：先制定计划、把子任务委派出去让子智能体在短上下文工作、在早期轮次变成负担前总结。

**01c 规模化工具**回答了"工具多了怎么办"，四个递进：

1. **多工具选择** —— 模型靠 `description` 和参数模式选，所以"工具名与说明必须和实际操作语义一致"（讲师原话："用 add，不要用 X、Y、Z"）。
2. **换后端不换约定** —— 工具名应该描述**能力**而不是后端（`glossary_search` 好过 `nvidia_glossary_api`）。
3. **把整个智能体藏在一个工具后面** —— 实现的是上下文分离，**不是**数据访问控制。
4. **MCP** —— `tools/list` 提供模式、`tools/call` 分派调用；响应要当作不可信输入（身份、能力、最小权限、token 受众、SSRF 防护）。

### 模块 2 · 高级模式：把控制权从模型手里拿回来一部分

**02a 工作流**的核心区分只有一句：**模型什么时候做决定**。

- **ReAct**：边看边决定，路径运行中才形成 —— 适合"下一步取决于最新观察"。
- **ReWOO（无观察推理）**：工具跑之前先用一次 LLM 写完整计划，确定性执行器并发跑完所有工具，第二次 LLM 调用才综合 —— 整个流程**只要两次模型调用**。

围绕这个区分，这一页给了三种"结构化"手法：

| 手法 | 做法 | 例子 |
|---|---|---|
| **路由（triage）** | 用固定枚举把工单分给一个专家，越界就拒绝或严格重试 | `{category: network/hardware/software/account, priority: high/medium/low}` |
| **分发（fan-out）** | 一次共享检索，`Promise.all` 并行给多个专家 | 三位专家 + 甘特图对比串并行耗时 |
| **工厂** | 把角色、系统提示词、工具、调用方式做成参数 | `createSpecialist({role, systemPrompt, tools})` |

这一页也诚实地点了拆分的代价：每个边界都增加延迟、增加消息格式出错的机会、把一条清晰时间线变成分叉轨迹 —— **拆之前先测延迟和质量**。

**02b 索引智能体**（RAG）是模块 2 里最"厚"的一页，14 个小节。它的方法论开头就给了：**先定义上下文包，再选存储方案**（"打算在工作流里传递哪一组完整且边界明确的上下文"）。

然后是一串"祛魅"式的技术递进：

- **检索原语要按数据形态选**：非结构化文本 → 稠密向量 + 交叉编码器重排；层次文档 → 带父节点指针的树；表格 → 语义层；图 → 图遍历（Cypher/GraphQL）。
- **嵌入就是向量**，比较只需要"一次点积加两个模"。
- **三十行 top-K 余弦就是一个完整检索器** —— "向量数据库"很大程度只是包装。
- **搜小块、返回父文档** —— 两层索引：小块嵌入利于命中，父文档完整利于生成。
- **包成工具** —— 由模型决定要不要检索，而不是每次都固定检索。
- **GraphRAG** —— 索引阶段用 LLM 抽实体关系建图、检测社区并分别总结，查询时汇总社区摘要：**结构上的 MapReduce，而不是相似度查找**，用于"top-K 不适用"的全局问题。

最实用的一条工程陷阱：**NVIDIA 嵌入模型用 `input_type`（`"query"` / `"passage"`）区分查询与段落，互换会改变分数、降低检索质量，而且不报错**。另外向量索引是嵌入模型输出的缓存，换模型、提供商悄悄升级、两个服务共享索引却固定不同模型 ID —— 都会让它失效。

**02c 深度智能体**把问题推到"证据规模超出单次对话容量"。它诊断得很清楚：单个 ReAct 循环里所有指令与观察挤在同一段历史，最终**历史本身成为问题** —— 溢出、上下文退化、分支之间互相干扰。

解法是把控制流从循环升级成图：

| 角色 | 拿到什么 | 产出 |
|---|---|---|
| planner | 原始问题 | 一组相互独立的子任务 |
| 子智能体（每个） | **只有**原始问题 + 自己的任务 + 所需工具 | 写到虚拟文件系统（`state.vfs`）的草稿 |
| 综合阶段 | 读回所有草稿 | 带引用的答案 |

这里有一句必须记住的提醒：**全新上下文不是沙盒**。上下文隔离解决的是"推理互相干扰"，沙盒解决的是"能不能碰操作系统" —— 两件不同的事。而且这一页的示例是**依模型自身知识撰稿**，工作智能体有文件工具但没有检索工具或来源，所以那些文件是草稿，不是核实过的证据。

### 模块 3 · NemoClaw 设置：从"页面里的玩具"变成"常驻的东西"

前面两个模块的智能体有个共同点：**浏览器关掉，一切结束**。模块 3 把它搬到本地 NemoClaw 运行时上，于是它有了持久的工作区、记忆和日程。

**03a 连接 NemoClaw** 是一次标准化的"接通 + 对照"：

- 检查**四条路由**：`/api/agent`（元数据与网关 token）、`/cli/gateway`（网关 WebSocket）、`/ws/terminal`（终端 WebSocket）、`/healthz`（健康）。
- 建立**只用模型的基线**：直接发一次 Chat Completions，记录 TTFT，作为"不经任何沙箱绕行"的对照。
- 再用 `operator.admin` 令牌做网关握手，调 `models.list`、`cron.list`，用新 `sessionKey` 流式 `chat.send`，最后 `sessions.reset` 演示"历史清掉但工作区文件还在"。

这一页埋了一个后面要炸的伏笔：**能读到本地运行时环境的人就能读到那个 token，而持有它的人拥有 operator 级别的全部权限**。模块 4 就把这个"便利机制"变成了核心安全问题。

**03b OpenClaw** 打开了智能体视角的黑盒 —— 一张工作区文件对照表，说明每个文件喂给提示词的哪一部分：

| 文件 | 作用 |
|---|---|
| `SOUL.md` | 角色、边界、语气、价值观 |
| `AGENTS.md` | 操作指令和规则 |
| `IDENTITY.md` | 名称、设定、风格 |
| `USER.md` | 用户身份与偏好 |
| `TOOLS.md` | 各工具使用说明 |
| `HEARTBEAT.md` | 周期性自主任务清单 |
| `memory/YYYY-MM-DD.md` + `MEMORY.md` | 按日笔记 + 整理后的长期记忆 |
| `skills/` | 技能 |

方法论上最有价值的是**"说得对不等于做对了"**：让智能体描述自己，然后用沙盒外的 operator 终端（`openshell sandbox connect <agent>`）把文件读回来对照，再检查工具事件。因为"回答只反映框架纳入提示的内容，加上工具读取的内容" —— 自述本身不是证据。

这一页还实际演示了**攻击面**：只要提示词能诱导它改 `MEMORY.md`（或 `SOUL.md`），下一次运行的行为就变了。讲师在录音里把这个说得很直白："soul.md 又注入给模型，它改变了大模型的行为，那么这些行为改变有可能就是 —— 他越狱了。"

**03c 持续运行** 讲"不用人开口也会跑"，用三个参数描述每种机制：**会话（继承谁的上下文）+ 指令（要它做什么）+ 触发器（什么时候开始）**。

| 机制 | 会话 | 触发 | 课程里怎么用 |
|---|---|---|---|
| 技能（skill） | 复用调用方会话 | 被明确指定或被选中 | `workspace/skills/<name>/SKILL.md` + 操作手册 |
| 心跳（heartbeat） | 主会话 | 网关计时器（约 30 分钟） | 只讲概念 |
| cron | 隔离会话（每次新建） | 单次/周期计划时间 | `cron.list` / `cron.add` / `cron.remove` |
| 子智能体 | 新建会话 | 父智能体在轮次中指派 | 只讲概念 |

判断"计划任务真的跑了"的唯一凭据是**执行记录 + 内容匹配的新文件（带参考码）** —— 因为成功的响应、成功声称、甚至 exit code 0 都不等于事情做成了。

### 模块 4 · OpenShell 安全机制：把"凭什么"落到内核

**04a OpenShell** 是全课程最有分量的一页。它先把"防御"分成三层，说明只有最后一层能被强制：

| 层 | 由谁负责 | 能做什么 | 为什么不够 |
|---|---|---|---|
| **提示词** | 系统指令、规则 | 塑造意图 | 模型仍可能被对抗性检索内容、恶意工具输出或对等智能体骗过，且仍保留运行时授予的全部权限 |
| **智能体工具框架** | OpenClaw / Hermes | 在请求到达 OS 前拒绝不支持的 shell 形式、禁用的工具、畸形参数 | 这是应用逻辑，可能配错、版本过时或被入侵 |
| **沙盒** | OpenShell | 只授予策略允许的权限；前两层都没拦住时，OS 仍在操作完成前拒绝 | 这是**唯一能强制执行**的一层 |

然后它把"安全"翻译成**四个可测试的问题**，每个都对应一个具体机制：

| 问题 | 机制 | 具体做法 |
|---|---|---|
| ① 这个进程能连到哪里？ | netns + HTTP CONNECT 代理 + **OPA** | 网络命名空间隔离网络栈，出站初始全关，CONNECT 代理是唯一出口；OPA 按**发起二进制、主机、端口、路径（+HTTP 方法）**判定 |
| ② 它能访问哪些文件？ | **Landlock** | 把新的文件操作限制在策略授予的路径（工作区目录树）；`best_effort` 模式 |
| ③ 它能请求哪些内核操作？ | **seccomp** | BPF 允许列表，被拒调用在**执行前**返回 `EPERM`；`ptrace`、`mount`、`setuid` 等被挡 |
| ④ 它最初拥有多大权限？ | **进程身份** | 以非 root 的 `sandbox` 用户运行；初始权限小，但这不证明不会提权（capabilities 仍是边界的一部分） |

两个理论依据值得记住：**最小权限**（Saltzer & Schroeder, 1975）、**评估边界而非证明意图**（由 Rice 定理：对任意程序的非平凡行为无法通用判定，所以不要指望静态检查能证明未来每步都安全）。

页面还训练了一套**"证据而非直觉"**的方法：读实时策略（`helpers.policyGet()` → `openshell policy get <agent> --full`）→ 静态预测（`helpers.evalSandboxNetwork` / `evalSandboxFs`）→ 在沙箱里实测（`openshell sandbox exec`）→ 对比是否一致。
这套方法自带三个"证据的边界"警告：命令失败**不能**指出是哪一机制拦住、预测与实测一致**不能**证明覆盖了全部规则、**读权限不能证明写权限**。

最后是整门课的收束：**沙箱拦不住的风险**。

- **致命三要素（lethal trifecta）**：私有数据 + 不可信输入 + 对外通道。三者同时具备，智能体就不可靠。策略可以正确允许某个出站 API 入口，但那个入口是**全双工**的 —— 允许列表批准的是目标地址，不是获准连接里字节的含义。
- **五类故障模式 → 控制措施**对照表（目标劫持/提示词注入、工具滥用、身份或权限滥用、供应链攻击或意外代码执行、记忆或上下文污染），每一类都分成"沙箱能管的部分"和"仍需在沙箱上层补的控制"（输入来源追踪、审批、逐工具授权、参数校验、速率限制、token 最小化与轮换、审计、可审查历史、从已知良好状态恢复）。这张表与 OWASP Top 10 for Agentic Applications 对齐。

**04b 现代 CLI** 把镜头抬高到应用封装层。它先说明所有对比对象其实是同一个东西 —— **一个工作目录 + 一组工具 + 一套记忆 + 可选的无人值守运行 + 网络访问** —— 差别只在默认设置与内置能力，这些成本与便利性合称"框架负担"。

各产品的默认设置差异（这一页最有实用价值的部分）：

| 产品 | 指令文件 | 默认放行/审查 |

## 五、把 11 个课时串成一条线

抛开模块划分，全课程其实在反复做同一件事：**把"该由模型决定的"和"该由代码强制的"分开**。

| 层次 | 该由模型决定 | 该由代码/机制决定 | 对应课时 |
|---|---|---|---|
| 循环 | 下一步做什么 | 循环何时退出、参数是否合法 | 01a 01b |
| 工具 | 调哪个工具、传什么参数 | 工具是否存在、参数是否合模式、后端是谁 | 01c |
| 结构 | 分支内怎么想 | 有几个分支、怎么汇合、枚举值合法否 | 02a 02c |
| 知识 | 该不该检索、怎么用证据 | 检索原语、索引一致性、`input_type` | 02b |
| 上下文 | 怎么理解 | 哪些文件进入提示词、记忆怎么存 | 03b 03c |
| 权限 | 想做什么 | 能做什么（文件 / 网络 / 系统调用 / 身份） | 04a 04b |

五条贯穿全课的判断，可以直接当结论记：

1. **骨架固定、推理可换** —— 循环结构一次建好，从 `if` 换到 DFS/BFS/A* 再到 LLM，状态布局和行动步骤都不用动。
2. **约定不变、后端可换** —— 工具名描述能力而非后端；换掉执行器不影响模型侧。
3. **先定上下文包，再选存储方案** —— 先想清楚"要传哪一组完整上下文"，再决定用向量、树、语义层还是图。
4. **隔离上下文 ≠ 沙盒** —— 前者解决推理干扰，后者解决 OS 权限；两者不能互相替代。
5. **边界可强制，含义不可强制** —— 沙箱能限制"能不能发"，不能判断"发了什么"；所以还需要输入来源追踪、审批、最小权限 token、审计。

## 七、三个最值得单独记住的技术细节

1. **`finish_reason` 是循环的唯一退出条件。**
   不是"模型说完了"，而是这个字段：`"stop"` 有最终答案、`"tool_calls"` 要求执行函数、`"length"` token 用尽、`"content_filter"` 被拦。讲师现场演示得很干净：问"用一句话说明智能体是什么"→ `stop`；问"现在几点"→ `tool_calls` 且答复字段为空。

2. **三十行代码就是一个完整检索器，但对称与非对称不一样。**
   `embed(query, {inputType:"query"})` → 逐段 `cosineSim` → `sort` → `slice(0, k)` → 拼进提示词。难点不在代码，在 **`input_type` 必须查询用 `query`、语料用 `passage`** —— 互换不报错，只是检索质量悄悄变差。而且 top-K 永远返回 K 条，即使分数都很低，所以入提示词前要看分数信号。

3. **OpenShell 的四个问题对应四个内核机制，一个都不能省。**
   网络（netns + CONNECT 代理 + OPA 四元组）、文件（Landlock）、系统调用（seccomp 允许列表，`EPERM`）、身份（非 root `sandbox` 用户）。四者回答的是**可测试**的问题，而不是"它是否有恶意"这种不可测试的问题。

## 附：一页速查卡

**这门课的骨架**

```
感知 → 推理 → 行动      （循环不变，换掉中间的决策函数）
      ↑___________|
```

**把循环变成产品，只需要三个字段**

| 字段 | 决定 |
|---|---|
| `messages[]` | 记忆（每轮重发，模型永远无状态） |
| `tools[]` + `finish_reason` | 能不能动手（`tool_calls` / `stop`） |
| `tool_calls[].function` | 动手做什么（名称 + 参数，需校验） |

**把智能体关进笼子，只需要四个问题**

| 问 | 答（机制） |
|---|---|
| 它能连到哪？ | netns + CONNECT 代理 + OPA（二进制 / 主机 / 端口 / 路径） |
| 它能碰哪些文件？ | Landlock（只放行工作区目录树） |
| 它能请求哪些内核操作？ | seccomp 允许列表（`EPERM`） |
| 它一开始有多大权限？ | 非 root 的 `sandbox` 用户 |

**三句要记住的判断**

1. 沙箱批准的是**目标地址**，不是那条连接里字节的含义 —— **边界可强制，含义不可强制**。
2. 自述、成功响应、exit code 0 都**不是证据**；执行记录 + 独立读回的内容才是。
3. 给智能体建围栏的不能是智能体自己 —— **防护要在进程外**。
