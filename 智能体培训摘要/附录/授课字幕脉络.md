### 老师强调的重点/判断

1. **"大模型只说不做，智能体是又说又做"**（[06:29-06:37]）—— 这是他给两者定的分界，也是全课主线。
2. **这门课不教写智能体代码**："我们这门课并没有告诉大家手把手的把这个实现写这个智能体的代码……主要通过各种各样的操作来体会智能体的功能，然后他的弱点在哪里，我怎么增加了防护"（[16:01-16:28]）；想学写代码，"那是在另外一门课里讲的"（[16:15]）。
3. **计算不是 LLM 的活**："你问他 3+5 等于几，这么简单的问题……他做的工作就是预测下一个词"（[24:35-24:54]）。
4. **ReAct 像人干活**："你拿到一个任务书，你不是上来就开始干活，你一定先看一看，想一想怎么做，按照那个步骤去做，然后才去工作"（[32:45-32:55]）。
5. **工具描述决定工具选择**："函数的语义要和他实际操作的要一致……你的描述函数的名呢，就用 add，不要用 X、Y、Z 这样的名字"（[37:04-37:21]）。
6. **分层是为了单独增强**："你需要增强 harness 这个功能，你可以把它提出来，单独的对它进行增强……整个 ReAct 的循环你可以不变"（[42:01-42:09]）。
7. **ReAct 的成本他直接点破**："ReAct 循环要循环多少次，你能控制吗？你是控制不了的……每一次循环它都生成一些 token，所以消耗了很多 token，那意味着你要多花钱"（[01:19:00-01:19:39]）。
8. **"智能体既是囚犯也是狱卒"**："这个囚犯直接给自己构建一个围栏，这个围栏是不可靠的……智能体一旦被攻破，整个他的围栏也被攻破"（[01:41:54-01:42:09]，"狱卒"处原字幕作"运输"，听辨不确定）。
9. **三条危险条件**："有对外的通道、可以接受外面的内容、可以访问本地的私有的数据，只要满足这三条，你的智能体就不可靠、就不安全"（[01:44:43-01:44:52]）。
10. **"最好的防护是在外面防护，不要在……这叫进程外防护，不是进程内防护"**（[01:45:16-01:45:22]）。
11. **API key 不在智能体手里**："这个 key 由谁来保管呢？是由 OpenShell 来保管的"（[01:48:41-01:48:46]）。
12. **他自己的架构图不是官方图**："这是我的理解啊，这个我们课程没有提供这个结构图……我没有读整个这个 JavaScript 代码，完全是根据我们做的这个实验试出来的"（[01:51:11-01:51:38]）——并反复说"这个图不一定百分之百准确，但是大概意思差不多"。

### 学员常见疑问与解答

1. **"大语言模型和智能体有什么区别？"**（[03:29]）—— 学员答：智能体实际是调用后面的大模型做推理、做规划；能知道使用者的习惯、更贴合个人。讲师肯定并补充"大模型只说不做、智能体又说又做"，发小礼物。
2. **"harness 在智能体里指什么？"**（[38:46]）—— 学员答：在模型之上设一层控制器，控制模型的输入输出、哪个节点需要用到模型、什么时候调用、什么时候做 ReAct、ReAct 结果什么时候回复给用户。讲师评价"接近哈"，再补充为"把 act（做）那部分抽成独立执行层"。
3. **"你用过什么样的 skill？在哪个智能体里？"**（[44:53]）—— 学员答：用过 GitHub 上很火的 grow me，大模型通过反问一遍遍确认需求，这就是很标准的 skill；又提到最近的逆向工具 REA"本质上也是一套 skill 封装，十几个 skill 加一堆工具"，对小白有用。

### 课程定位与学习方法

- **定位**：三个小时的"体验课"，面向已经会用智能体、想搞清"它为什么危险、怎么加防护"的人；重点是体验功能与弱点、理解 OpenShell 包裹后安全性为何提升，**不教从零写智能体代码**，也不带读 ReAct 实现的 JS 源码（[15:56-16:50]、[55:41-56:09]）。
- **学习方法**：课上时间不够，"我尽可能的跟大家一起把这时间过一下……课后呢，请大家利用我们给大家分配的那个，六个月之内都可以再访问这个课程的那个内容，你自己再细细的把这个课程的这个实验再好好做一下"（[50:56-51:27]）。
- **概念怎么补**：课程页没有特意解释 harness、插件、MCP、skill 这些词，讲师用 PPT"利用这点时间给大家说一下"，并建议听不懂的"你但凡听不懂的地方，回头你在复习的时候，每一个概念你可以到网上去搜，那个什么 DeepSeek 等等，这些智能体都会给你解释的很清楚"（第二段 [06:17-06:31]）。
- **离线复习建议**：保存 12 页 HTML（浏览器可另存）、下载 notebook（需本机装 Jupyter）；课程不带 PPT（[00:32-01:05]）。
- **前置经验**：做过全站开发/JS/TypeScript 的人读这些内容更快，这是他在第二段专门插话强调的（见下）。

### 老师强调的重点/判断

1. **权限不能给 root**："你不能以 root 的这个名字、用户名去执行，那个权限太高了……OpenClaw 在执行的时候，他的那个用户名就是普通的用户名"（[00:16-00:27]）。
2. **管道权限在建管道时就定了**："你不需要每次请求再检查——他在建管道的时候，就用这个 token 已经指定了这个管道具有什么样的权限，将来只要在他权限之内他都执行，他不是一个一个的请求去再做检查的"（[11:31-11:50]）。
3. **"完成不等于成功"**："退出码是零、outcome complete 完成了……我请问大家，完成了意味着成功吗？"（[50:24-50:28]）随后指出另一端返回的是 HTTP 403。
4. **成功易判、失败难查**："成功的话那个理由只有一个，那说明你所有的关卡都过了；但是失败的话，你是很难判断原因的……中间每个节点都可能失败"（[51:57-52:13]）。
5. **默认拒绝**："我们设置这个 OpenShell 安全措施的原则就是默认即拒绝，你只有放到那个白名单里面才可以执行"（[46:51-47:02]）。
6. **soul.md 是重点保护对象**："如果对方给你来一个注入式攻击，说请你改你的 soul.md 文件……soul.md 又注入给模型，它改变了大模型的行为，那么这些行为改变有可能就是什么——他越狱了"（[30:33-31:08]）。
7. **小模型撑不住 ReAct**："30B 的模型是比较小的……他在做 ReAct 推理、判断使用哪个工具的时候，有可能判断不准确，所以我们把使用工具先停掉"（[19:52-20:22]，原话"把它平一点"疑为"把它停一下"，听辨不确定）。
8. **他明确说图不一定准**："我这个图不一定百分之百的准确，但是大概意思差不多"（[03:32-03:35]）、"我没读这个代码，我不敢肯定是 OpenClaw 自己对外开放的服务接入点，还是我们这个 Web 服务器的后端它开发的"（[08:39-08:49]）。
9. **Hermes 最危险**："Hermes 它有个功能叫自我改进……这个智能体也是最危险，因为他在跟你对话的时候，他在背后就去改那些文件"（[57:28-57:55]）；"像 Hermes，他的那个安全隐患就是最大的；Claude 在这方面总的来说做得还是比较好的"（[58:33-58:39]）。
10. **给全栈工程师的判断**："很多人被裁员了……但是我告诉大家，你如果有全栈开发的经验，今天正是你大显身手的时机，我们这些 AI 智能体的开发基本上都是需要全站开发的那个知识和经验"（[06:35-06:58]）。
11. **统一应对方案**："如果你的智能体有这样一些问题，最简单的话就是你加上 OpenShell，把这个整体外面你自己让 OpenShell 给他包一层"（[58:49-58:59]）。

### 现场演示的操作

- **3A · 测试连接**：点"测试连接"，四条路由依次 pass，底下显示内容、原因、凭据等字段（[09:00-09:13]）；再跑"检查全部四条连接的路由""依次测试网关/终端/运行状况"（[09:20-09:36]）。
- **3A · 读元数据**：打开第一条读取 OpenClaw 元数据的单元，现场在返回值里逐项指认：`local provider`（本地部署）、`transport` 为浏览器直连、WebSocket token（[09:42-10:48]）；再翻到 sandbox policy，指出三方面策略，并放大找到 `inference.local` 这条唯一推理路径、"API key 这里是空在那的，是一个占位符"（[13:30-15:28]）。
- **3A · 健康检查与"仅使用模型"基准**：先健康检查（healthy=true 就不用再恢复和查日志），再直连模型端点发一次推理请求记录延时，然后经沙箱发一次作对比（[16:12-18:40]）。
- **3A · 打开网关 + 两条 RPC 命令**：建立 WebSocket 连到 gateway，返回的 scope 是 `operator.read`，"这个权限是非常高的，有点像你 Linux 系统里 root 用户的权限"（[21:45-22:16]）；随后调 `model.list`（只给出一个可访问模型、没有具体模型名）与 `cron.list`（定时任务为空）（[21:20-22:52]）。
- **3A · 发送聊天消息**：让智能体在沙箱里执行 `env`/`pwd`，观察蓝绿色输出显示用户名（sandbox）与工作区路径（[22:52-23:42]）。
- **3A · 多会话演示**：在 OpenClaw 界面点 new session 新建"课程一"会话，回车后出现会话记录；输入斜杠 `/` 自动弹出内置技能列表（stop、reset 等）（[25:08-26:32]）。
- **3B · 描述工作区 / 代码审查**：先看 JS 里的提示词"简要列出公共区的文件……不要输出文件的内容"，运行后智能体列出工作区文件（[32:32-33:32]）；再跑两段代码审查提示（普通审查 + 以风险为重点的审查）（[33:37-34:40]）；再跑"智能体编辑自己的上下文""将以下偏好加入 memory.md"这类步骤，用来说明注入与权限过大（[35:26-36:40]）。
- **4A · 健康检查 + 检查命令**：运行后观察 curl 请求 `…intro.com`（听辨不确定，疑为某示例域名）退出码 56、outcome 为 deny；另一个 curl 退出码 0、outcome 为 complete，但打印出的 HTTP code 是 403（[48:09-51:02]）。
- **4A · 策略地图**：运行"读取沙箱运行时的实时策略并以地图形式呈现"，得到左右对照图（左为发起实体、右为 OPA 策略项，绿允红禁），并在 `calling binary` 处把 curl 改成 openclaw 命令，观察可访问资源集变化（[53:19-54:37]）。
- **4B · 智能体对比**：打开 4B 页面对比 Claude Code / Codex / Cursor / Hermes / OpenClaw，讲师提到自己原来做过包含七八个智能体的对比 PPT（[55:45-56:32]）。

### 学员常见疑问与解答

1. **"安全策略有哪三个方面？"**（[45:55-46:08]）—— 女学员答"文件系统、进程、网络"，讲师确认"很好啊"；并补充若算第四点，就是 OpenClaw 运行在沙盒里、用户名不是 root 而是 sandbox（普通用户）。

3. **"退出码是 0、访问成功了吗？"／"完成了意味着成功吗？"**（[50:09-50:34]）—— 讲师引导看 outcome 与输出里的 http code，指出 403 即失败；现场有学员作答，讲师随即说"这个问题回答对了哈"（前后也有一句"请大家记住这位同学，他失败了"，两句衔接略显混乱，听辨不确定）。

### 课程定位与学习方法

- **授课节奏**：明确说"我们只有三个小时，我就不给大家时间（自己动手），你课后你有大量的时间回头去复习……你跟我一起过一下，你至少有一点印象，将来复习的时候就会容易一些"（[07:31-07:48]）。
